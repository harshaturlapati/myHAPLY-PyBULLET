myHAPLY-PyBULLET

Read the Haply Inverse3 at 1 kHz from C++, on Windows or the lab Raspberry Pi, and build haptics on top of PyBullet. This page walks you from a fresh fork to your first log, and on to your own pull request.

    2 · Prepare the device

    Tick these off before every session. Your ticks are kept in this browser only.

    3 · Run 01_read_fbk

    Set the options and copy the command. Press Q (or Ctrl+C) to stop. The CSV log lands in logs/.

    
    
    What you should see: device id and UUID, raw joint angles, ten test samples, then one line refreshing
      with X (m), V (m/s) and the achieved rate. If it says NOT CALIBRATED, go back to step 2.
      On the lab Pi a 1 kHz loop keeps the device round trip near 0.15 ms; --rate 0 reaches about 7.9 kHz.
    
    
    Running on the lab Pi from your laptop
      
    Ask the lab admin to add your SSH key to the Pi, then ssh in and run the Linux commands there.
        The examples read the keyboard over SSH, so Q works remotely too. Copy logs back with
        scp <user>@<pi>:myHAPLY-PyBULLET/logs/*.csv .

    6 · Contribute through your fork
    
  
    Work in your fork, then send a pull request to the main repository. The commands use the username from step 1.
    
  
    
    
      
    
      Template for a new example
      
    
      
    
      Pull-request checklist
      
    
      ☐Builds with CMake on at least one OS. Say which (Windows / Pi / other) in the PR.
      
    
      ☐Ran on the real device. Attach a screenshot or a short CSV excerpt.
      
    
      ☐Forces stay below F_max; the program sends zero force before it exits (quick_stop()).
      
    
      ☐Device code stays in libs/; the example is short and has a header comment saying what it does.
      
    
      ☐No build/, logs/, CSVs or Haply binaries committed.
      
  
      

      



      
  
      Protocol reference
      
  
      What libs/myHAPLY_v1.h sends over the USB serial port. Floats are 32-bit little-endian.
      
  
      
    
      
      
      PurposeComputer sendsInverse3 answers
      
      
        
      Wake up (first, always)0A0B + id (u16) + 3 bytes + 16-byte UUID
      
        
      Cursor force → state2A + fx fy fz (N)2B + x y z (m) + vx vy vz (m/s)
      
        
      Joint torque → joint state1A + τ1 τ2 τ3 (N·m)1B + q1 q2 q3 (deg) + q̇1 q̇2 q̇3 (deg/s)
      
        
      Status event(none)BA + type + length + payload, at any time, e.g. on a mode change
      
            
    
      
  
      
  
      The force you send is held until the next command, so loops must keep sending, and must send zero before exiting.
    Not calibrated: the position is 0 and the velocity is 65535.
